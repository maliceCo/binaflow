# Personal web interface

Binaflow's browser interface is an attached, single-workspace server. It is not a
shared service or daemon. Start it with:

```bash
pnpm run cli -- web --web-config .binaflow/web.json
```

The command opens the normal Binaflow config once, starts one execution host and
one HTTP listener, and prints the URL and a fresh access code to stderr. The
access code is not persisted and changes on every start. `SIGINT` and `SIGTERM`
close the listener before the host releases SQLite and the data-directory lease.
A browser disconnect does not cancel an operation.

## Configuration

The web config is strict JSON. Relative certificate and source-key paths are
resolved relative to the web config file:

```json
{
  "host": "127.0.0.1",
  "port": 4317,
  "origin": "http://127.0.0.1:4317",
  "sources": { "searchKeyFile": ".secrets/brave-search.key" }
}
```

Loopback HTTP is allowed for local use. Any non-loopback bind requires an exact
HTTPS origin and both `tls.certFile` and `tls.keyFile`; Binaflow does not create
certificates or configure firewalls. LAN users must install/trust the chosen
certificate and the operator must restrict the network exposure manually.

The optional external search key is read by application composition when source
search is enabled. A missing key means search is unavailable; it is not inferred
from the browser or stored in the database.

## Browser E2E tests

The Playwright browser binary is installed separately from the pnpm dependencies:

```bash
pnpm run test:web:install
```

On Debian/Ubuntu hosts, install the native browser libraries once as an
administrator, then run the tests:

```bash
sudo pnpm exec playwright install-deps chromium
pnpm run test:web
```

The project config runs Chromium with one worker, retries once in CI, and keeps
trace/screenshot/video evidence only for failed tests. The tests are attached to
the current process; they do not start a daemon.

## Limits and guarantees

- Sessions are HttpOnly, SameSite, in-memory, capped, and expire after eight
  hours. Login is rate limited by client address and globally.
- Mutating requests require the exact configured `Origin`, `Host`, JSON content,
  and an in-memory CSRF token. Request bodies are bounded.
- The API is versioned under `/api/v1`; task and operation DTOs contain IDs,
  versions, statuses, and safe document headers, not filesystem paths, tokens,
  transcripts, or artifact internals.
- Preparation operations retain their request ID and expected revisions. Retry
  with the same request ID is the reconciliation path for an ambiguous response;
  a new ID is not generated by the browser after a network error.
- The browser stores no credentials in local storage. A hash identifies the
  selected task, and React renders returned content as text.
- This preview does not provide a terminal, arbitrary filesystem/config access,
  CORS, a daemon, remote workers, or execution that survives host shutdown.

The browser workflow is separate from legacy CLI/TUI preparation, but it uses
the same task-contract and schema-15 persistence. Schema-14 portable backups
remain importable; schema-15 exports include guided conversations, sources, and
idempotent requests. Live Pi/model behavior and access from another LAN machine
remain operator validation items, not claims made by local tests.
